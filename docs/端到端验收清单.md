# 端到端验收清单（阶段 5）

> 用途：在可运行的部署环境（Cloudflare Sites 或自托管 Docker）中，用五类账号跑通
> 完整工作流，验证状态、权限、通知、凭据与审计始终一致。

## 一、前置条件

1. 部署为 Private / 受限访问，未开放公开注册。
2. 准备 5 个真实账号：系统管理员、主席、负责人、干事、教师（对应系统五个角色）。
3. 先在管理员「账号与权限」里按真实邮箱开通这 5 个账号并分配身份（自托管时设置密码）。
4. 初始化一次空数据（不要沿用演示种子数据）。

## 二、每角色验收

### 管理员（技术身份）
- [ ] 创建/编辑/停用账号；停用后该账号访问被拒（403）。
- [ ] 查看审计日志（`/api/audit`），能看到任务/子任务状态转换记录与操作人。
- [ ] 导入换届成员（Excel），逐行校验、错误可读、无静默失败。
- [ ] 配置学年学期起止日期；系统配置保存生效。

### 主席
- [ ] 创建活动（名称/时间/地点/对接教师/参与部门），活动中心以卡片展示。
- [ ] 发布主任务（选活动或独立事务；负责人或直接干事；截止时间；管理模式；动态参数）。
- [ ] 主任务详情看到所有子任务的执行人、状态、凭据、动态。
- [ ] 审核负责人结办：通过 / 退回（填原因）/ 重新打开。

### 负责人
- [ ] 工作台看到本部门主任务（看不到其他部门）。
- [ ] 在主任务详情内拆解子任务并分派（不能脱离任务上下文分派）。
- [ ] 验收干事交付：通过 / 退回修改（必填原因）；直接办结；撤销子任务（记录原因）。
- [ ] 提交部门结办；撤回未审核的结办并重新提交。

### 干事
- [ ] 只看到分配给自己子任务；直接交办的主任务也可见。
- [ ] 开始 → 上传凭据（图片/文档）→ 提交验收 → 撤回再改再提交。
- [ ] 无法修改/删除他人子任务或凭据。

### 教师
- [ ] 仅查看授权范围内的活动与进展；提交指导意见并通知主席/负责人。
- [ ] 不参与学生组织内部任务分派链。

## 三、跨角色完整工作流（示例：十佳歌手比赛）

1. 主席建活动 → 给运维部发布「舞台技术保障」主任务（负责人确认模式）。
2. 运维负责人拆解为设备检查/彩排值守/灯光音响等子任务，分派给干事。
3. 干事 A 开始「设备检查」，上传照片凭据，提交验收。
4. 负责人退回一次（填原因）→ 干事修改重新提交 → 负责人验收通过。
5. 干事 B 的子任务被负责人撤销（收到通知，记录原因）。
6. 负责人提交部门结办 → 主席退回一次 → 负责人重新提交 → 主席审核通过。
7. 教师对活动提交指导意见 → 主席/负责人收到通知。
8. 活动完成后，管理员按学年学期归档资料（保留来源活动与任务）。

## 四、安全 / 越权 / 并发 / 一致性

- [ ] 直接调用 API 越权测试：干事尝试 `PUT /api/state` 的 tasks/subtasks 键 → 403。
- [ ] 干事直接调用转换端点操作他人子任务 → 403；操作自己子任务 → 成功。
- [ ] 主席 A/B 两个浏览器同时改同一任务：后提交者收到 409「数据已被其他成员更新」。
- [ ] 父子状态聚合：子任务开始后，主任务在所有概览中同步为「进行中」。
- [ ] 通知：状态变化后对应角色收到通知，可从通知跳转到对应实体；已读状态跨设备一致（服务端回执）。
- [ ] 附件：上传失败显示原因；删除附件后不可再访问；R2/对象存储键为 `tasks/日期/uuid.ext`，数据库只存键与元信息。
- [ ] 审计：以上每次状态转换在审计日志中可追溯（实体/动作/前后状态/操作人/时间）。

## 五、跨设备一致性

- [ ] 主席与负责人各用一台设备/浏览器，一端改状态后另一端刷新看到同一状态、附件与通知。
- [ ] 通知已读状态为个人数据，不同账号互不影响。

## 六、上线前收尾

- [ ] 删除验收期间创建的测试任务、测试附件与测试账号。
- [ ] 导入真实成员前再次核对届次/部门/职务。
- [ ] 确认仍为 Private，访问名单无无关邮箱；自托管时数据库/对象存储端口不暴露公网。
- [ ] 备份并实际演练一次恢复流程。
- [ ] `npm run typecheck`、`npm test`、`npm run lint` 全部通过。

## 判定标准

五类账号能在不同设备上完成各自的完整工作流，状态、通知、权限、凭据、审计全程一致，
且系统未给日常工作增加无意义负担 —— 即达到上线标准。
