# 国内自托管部署方案（阶段 4）

> 现状：应用运行在 Cloudflare Workers（D1 + R2 + 平台身份头）。
> 目标：在腾讯云轻量服务器或同类国内云主机上自托管，中国大陆可稳定访问。

## 一、目标架构

```
公网 :443 (HTTPS)
   │
   ▼
Caddy（反向代理 + 自动 HTTPS）
   │
   ├─ /api、/  → 应用容器（Node 22，Docker）
   │
   ▼
应用容器 ──┬─ PostgreSQL（替代 D1，关系数据）
           ├─ MinIO / 腾讯云 COS（替代 R2，附件对象存储）
           └─ 会话存储（服务端会话 + 密码哈希 / 学校统一身份认证）
```

- 对公网只开放 80/443；PostgreSQL / MinIO 管理端口不暴露。
- 附件大文件走对象存储，数据库只存对象键与元信息。

## 二、四端口适配层（已建立）

代码已抽象四个端口（`app/ports.ts`），业务层只依赖接口，不直接依赖 `cloudflare:workers`：

| 端口 | 接口 | Cloudflare 实现 | 自托管实现（待建） |
| --- | --- | --- | --- |
| `IdentityProvider` | `currentUser(request)` | 平台身份头 → 账号（`server-auth`） | 密码哈希 + 会话 / 学校 CAS/OAuth |
| `DatabaseRepository` | `prepare/batch` | D1（`env.DB`） | 已提供 Node/SQLite 实现（`platform/node-sqlite-db.mjs`）；PostgreSQL（`pg`）待建 |
| `ObjectStorage` | `put/get/delete` | R2（`env.FILES`） | 已支持 `setStorage()` 注入（测试/自托管）；MinIO / COS（S3 协议）实现待建 |
| `NotificationService` | `create/listReadIds/markRead` | 通知关系表 | 同一关系表（PostgreSQL） |

`app/platform.ts` 是组合根：目前返回 Cloudflare 实现（`getPlatform()`），并提供
`setDb()` / `setStorage()` 两个注入点，测试与自托管可替换数据库与对象存储实现。
新增 `app/platform-node.ts` 后，在组合根切换即可，业务层不改。

已接入端口的示例：`app/api/files/route.ts` 通过 `getPlatform().storage` 访问附件；
`app/db.ts` 的 `setDb()` 已被全部存储模块使用（含 `app/api/organization` 组织成员端点）。
四个端口均已被集成测试真实调用。业务层已不再直接 `import "cloudflare:workers"`——
仅 `app/db.ts` / `app/platform.ts` 两个组合根文件保留 D1/R2 实现；drizzle 查询构造器运行时
（`db/index.ts`）已移除，`db/schema.ts` 仅保留为 `drizzle-kit generate` 的表结构来源。

### DatabaseRepository 的 Node 实现（已落地）

- `app/db.ts`：`setDb(repo)` 可注入自定义 `DatabaseRepository`（自托管或测试用），传 `null` 恢复 D1 默认实现；`getDb()` 返回一个代理，每次方法调用转发到「当前生效」的实现，使测试可随时切换，不受模块缓存影响。
- `platform/node-sqlite-db.mjs`：基于 Node 内置 `node:sqlite`，对外提供与 D1 一致的 `prepare/bind/first/all/run/batch` 接口（含懒 prepare，支持 batch 内先建表后建索引）。
- 集成测试 `tests/integration.test.mjs` 在真实 SQLite 上运行，覆盖五层：
  - 存储层：`shared_state` 历史 JSON 一次性迁移、种子默认值、upsert 落库；
  - API 路由层：通过身份头（`oai-authenticated-user-email`）模拟五类账号，直接调用路由处理函数，验证服务端越权（401 / 403）真实生效（config/research/task-types/workflow-records/audit/accounts/notifications/state/activities/archive/notifications-read/organization）；
  - 主任务工作流：主席发布主任务 → 干事开始/提交 → 主席终审通过，逐笔校验状态随关系表推进；
  - 子任务工作流：负责人拆解分派 → 干事开始/提交 → 负责人验收，校验父子状态自动聚合；以及 teacher 路由层拒绝、非主席发布、干事越权审核/验收/拆解等拒绝路径；
  - 正式认证链路：管理员预建带密码账号 → 密码登录（正确/错误/不存在/停用）→ 会话 Cookie 读取 → 登出后会话失效（覆盖 `/api/login`、`/api/session`、`/api/logout`）；
  - 附件闭环：通过内存 `ObjectStorage` 桩走通 `/api/files` 上传→下载→删除（验证对象存储端口注入）。
- `tests/helpers/register.mjs` 用 `registerHooks` 把 `cloudflare:workers` 重定向到本地垫片，使依赖该模块的 `.ts` 文件可在纯 Node 下导入；测试命令为 `node --import ./tests/helpers/register.mjs --test-isolation=none --test tests/*.test.mjs`。
- PostgreSQL 适配已落地骨架：`platform/sql-dialect.mjs` 提供纯函数 `translateSqliteToPostgres`（`?`→`$1`、`INSERT OR IGNORE`→`ON CONFLICT DO NOTHING`，跳过字符串字面量内的 `?`）；`platform/node-pg-db.mjs` 提供 `createPgRepository`（懒加载 `pg`、可注入连接池），`tests/sql-dialect.test.mjs` 用假连接池验证翻译与绑定值传递。
- PostgreSQL 表结构：`platform/pg-schema.sql` 从 `db/schema.ts` 手工翻译而来（`SERIAL`/`BOOLEAN`/`TIMESTAMPTZ` 类型映射）；`tests/migration-consistency.test.mjs` 同时校验 SQLite 迁移链与 PostgreSQL 迁移的表/列均与 `db/schema.ts` 一致，并拒绝 `AUTOINCREMENT`/`PRAGMA` 等 SQLite 残留。
- PostgreSQL 剩余工作：存储模块里 D1 时代的运行时 `ensure*Schema`（`CREATE TABLE IF NOT EXISTS`）在 PG 下应改为「部署时执行 `platform/pg-schema.sql` + 运行时跳过建表」；时间戳列改为 `TIMESTAMPTZ` 后读取端由字符串变为 `Date`，个别字符串拼接需适配；接入 `pg` 依赖后在真实 PostgreSQL 联调。

## 三、Docker Compose 目标形态（示意）

```yaml
services:
  app:
    build: .
    environment:
      - DATABASE_URL=postgres://app:${DB_PASSWORD}@db:5432/union
      - S3_ENDPOINT=http://minio:9000
      - S3_BUCKET=files
      - SESSION_SECRET=${SESSION_SECRET}
    depends_on: [db, minio]
  db:
    image: postgres:16
    environment: [POSTGRES_DB=union, POSTGRES_USER=app, POSTGRES_PASSWORD=${DB_PASSWORD}]
    volumes: [pgdata:/var/lib/postgresql/data]
  minio:
    image: minio/minio
    command: server /data --console-address ":9001"
    volumes: [miniodata:/data]
  caddy:
    image: caddy:2
    ports: ["80:80", "443:443"]
    volumes: [./Caddyfile:/etc/caddy/Caddyfile, caddydata:/data]
volumes: { pgdata: {}, miniodata: {}, caddydata: {} }
```

> 数据库迁移沿用现有 `drizzle/*.sql`（D1 的 SQLite 语法），迁移到 PostgreSQL 时需
> 做方言适配（AUTOINCREMENT → SERIAL、布尔 0/1 → BOOLEAN 等），并保留一次性数据迁移。

实际部署文件为 `Dockerfile`、`deploy/docker-compose.yml`、`deploy/Caddyfile`、`scripts/backup.sh`
（上方 YAML 仅为目标形态示意）。`tests/deploy-config.test.mjs` 对这些文件做静态校验：
build 上下文、环境变量覆盖、备份脚本与反向代理一致性，随 `npm test` 一起跑，防止部署配置漂移。

## 四、认证

- 生产不允许公开注册；继续采用「管理员预建账号」。
- 密码使用 `argon2`/`bcrypt` 哈希，替换本机演示明文 `123456`。
- 优先接入学校统一身份认证（CAS/OAuth），次选账号+密码。

## 五、备份与监控

- PostgreSQL：每日 `pg_dump`，保留最近 N 天，定期演练恢复。
- 对象存储：每日增量同步到异地/冷存储，验证可下载。
- 应用日志：结构化 JSON + 集中采集；关键接口埋点（登录、任务状态转换、附件上传）。
- 健康检查：`/api/session` 探活；数据库/对象存储连通性检查。

## 六、ICP 备案提示

服务器位于中国大陆并使用自有域名需 ICP 备案。小范围测试可先用：受控测试服务器、
访问白名单、邀请码或管理员预建账号，但仍不得开放公众自由注册。
