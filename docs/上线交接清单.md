## 3. 怎么确认代码是好的（上线前必做，3 条命令）

在项目目录里，按顺序执行：

```bash
npm run typecheck   # 检查代码类型有没有错，应显示 0 错误
npm test            # 跑全部 96 项测试，应全部通过（会先构建一次，稍等）
npm run lint        # 检查代码规范，应 0 错误（可能有 6 条黄色 warning，可忽略）
```

**判定**：三条都「0 错误 / 全通过」，代码就是健康的，可以进入部署环节。

> 小提示：`npm test` 里的构建步骤需要联网，且在正规终端里跑（不要在受限沙箱里跑）。

## 4. 上线有两条路，先选一条

### 路线 A：继续用 Cloudflare（推荐，现在就能用）

- 系统的数据库（D1）、附件（R2）、身份认证本来就在 Cloudflare 生态里，**当前代码可以直接部署**。
- 项目里已经配好绑定关系：`D1 → DB`、`R2 → FILES`（见 `.openai/hosting.json`）。
- 适合：没有「必须国内服务器」的硬性要求。

### 路线 B：国内自托管（Docker + PostgreSQL + MinIO）

- 已有脚手架：`Dockerfile`、`deploy/docker-compose.yml`、`deploy/Caddyfile`、`scripts/backup.sh`、`platform/pg-schema.sql`。
- **但还没真正跑通**：缺 `pg` / MinIO SDK 依赖安装 + 真实联调，以及「运行时建表改迁移驱动」这一步。
- 适合：必须把数据放国内服务器、有备案域名。
- **这条需要开发接手完成，小白不要自己硬上。**

## 5. 路线 A 的详细步骤（Cloudflare）

> 具体「点哪个按钮」以你 Cloudflare 后台为准，这里给关键动作。

1. **建好云端资源**（在 Cloudflare 后台）：
   - 一个 D1 数据库，绑定名 `DB`。
   - 一个 R2 存储桶，绑定名 `FILES`。
2. **部署**：用你的部署方式（Cloudflare Pages/Sites，或部署命令）把项目发布上去；项目里 `.openai/hosting.json` 已声明绑定，部署平台会按它接上 D1/R2。
3. **设为私有 / 受限访问**（重要）：不要让陌生人访问。
4. **首次访问初始化**：站点所有者第一次打开，系统会把该身份设成「系统管理员」。
5. **开通账号**：管理员进「账号与权限」，按每个使用者的真实邮箱建账号、分配身份。
6. **用空数据验收**：不要导入真实成员，先用少量测试数据跑通一遍（第 6 节清单）。
7. **导入真实数据**：验收通过后，再在「组织与成员」里导入真实成员名单（有 Excel 模板）。

## 6. 上线后要做的验收（照着点）

完整清单见 `docs/端到端验收清单.md`。核心要验证：

1. **五类账号各跑一遍自己的流程**（主席发任务 → 负责人拆解 → 干事执行提交凭据 → 逐级验收/退回）。
2. **越权测试**：用干事的账号，直接访问「只有管理员能用的接口」，应被拒绝（403）。
3. **父子状态一致**：子任务一开始，主任务在所有页面都自动变成「进行中」。
4. **通知与审计**：每次状态变化，相关人收到通知；审计日志里能查到是谁、几点、从什么状态变成什么状态。
5. **附件**：上传 → 下载 → 删除，删除后不可再访问。
6. **跨设备**：主席和负责人各用一台电脑/手机，一端改完另一端刷新看到一致结果。

## 8. 遇到问题怎么排查

| 现象 | 先查 |
|---|---|
| `npm install` 报错 | 确认 Node 版本 ≥ 22.13，且能联网 |
| `npm test` 不通过 | 看是哪个测试红，把报错信息发给开发 |
| 页面打不开 | 确认部署状态、域名解析、是否设为 Private |
| 某账号进不去 | 到「账号与权限」确认该邮箱已开通、角色正确、账号是启用状态 |
| 附件传不上去 | 确认 R2 桶已建好、绑定名是 `FILES` |

## 9. 备份与回滚
