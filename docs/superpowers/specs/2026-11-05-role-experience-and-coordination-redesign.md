# 角色体验与协调工作台整改设计

日期：2026-11-05  
项目：计算学院学生联盟管理系统

## 1. 背景与目标

系统已经具备活动、任务、部门服务和教师监管等主要功能，但实际按角色走查后仍存在身份口径不一致、待办无法精准定位、教师写权限超出要求、专属业务待办分散以及主席缺少协调视角等问题。

本次整改不重写现有业务状态机和领域表，而是在现有功能上统一身份、权限、待办、详情和协调入口，使主席、负责人、干事、部门经办人、教师和管理员都能从自己的首页完成或查看应有工作。

成功标准：

- 本地与部署环境使用同一套服务端身份和权限逻辑。
- 每类测试账号均可真实登录，服务端按其角色和部门裁剪数据、校验写操作。
- “我的工作”可以直接打开目标记录，而不是只跳转到模块首页。
- 教师在所有入口中保持只读。
- 部门专属事项能够进入首页待办和统一工作队列。
- 主席能够看到跨活动、跨部门的风险与负荷信息。

## 2. 统一身份与权限

### 2.1 真实会话

所有账号统一存入 `app_accounts`，通过邮箱和密码建立服务端会话。本地环境不再把无会话请求默认为管理员，前端也不再使用浏览器本地身份代替服务端身份。

本地初始化管理员、主席、科创中心负责人、科创中心干事、办公室人员、学习部人员、新媒体人员和教师账号。测试密码统一为 `123456`，并在登录页标明仅用于本地测试。

退出登录后始终返回统一登录页，不在演示账号选择和邮箱登录之间产生不可恢复的跳转。

### 2.2 权限原则

- 管理员：账号、组织基础数据、系统配置、审计和运行状态，不参与普通业务处理。
- 主席：活动统筹、任务发布与终审、跨部门协调。
- 部门负责人：本部门任务拆解与验收、本部门专属业务办理。
- 干事：本人获派任务和本人发起事项。
- 教师：查看全部监管数据，不执行活动、任务或部门业务的写操作。

服务端权限是最终边界。前端隐藏、禁用按钮仅用于改善体验，不能代替服务端校验。

### 2.3 教师只读

删除教师端活动批准、退回、任务处理和提交指导意见等写入口。活动 API、任务 API 和部门业务 API 均拒绝教师写请求。教师仍能查看活动、负责人和干事任务、关联部门服务、附件成果、操作记录和健康状态。

## 3. 统一待办与精准跳转

### 3.1 工作项范围

统一工作队列继续使用来源索引，不复制领域数据。本期纳入：

- 主任务和子任务；
- 场地申请；
- 采购申请；
- 白卡制作；
- 例会通报；
- 组织成员异动；
- 组织事务。

每个工作项保存来源类型、来源编号、当前状态、下一处理人、发起人、负责人、部门、活动、计划时间、阻塞原因和更新时间。

### 3.2 待办口径

统一显示：等待我处理、我负责、我发起、即将到期、已逾期、已阻塞和最近完成。

通知中心承担一次性提醒，“我的工作”承担持续待办。通知已读不会让未完成工作从待办中消失。

### 3.3 精准打开

- 主任务：打开对应主任务详情。
- 子任务：打开父任务详情并定位、突出该子任务。
- 场地、采购、白卡、例会、组织事项：进入对应工作区并打开指定记录。

使用统一的导航目标对象传递来源类型和来源编号。目标打开成功后清除，避免刷新或返回时反复弹出。

若用户无权处理，则详情仍可在其可见范围内只读展示，并说明当前处理人和权限原因；若无权查看，则返回明确错误而不是空白页面。

### 3.4 部门首页待办

办公室首页聚合待审核场地、办理中场地、待汇总例会和采购报销交接；生活部聚合采购、查寝和失物事项；组织部聚合异动、考核和组织事务；学习部与新媒体中心聚合白卡交接。首页卡片和统一工作队列使用同一来源状态，避免数量不一致。

## 4. 任务控制与主席协调

### 4.1 执行控制

任务详情增加：

- 标记阻塞和解除阻塞；
- 改派负责人或执行人；
- 调整计划完成时间；
- 配置完成后开始的前后依赖。

所有调整必须填写原因。服务端保存调整结果并写入工作流事件，详情展示操作者、时间、原因及前后变化。前置任务未完成或任务处于阻塞状态时，开始操作返回明确提示。

### 4.2 活动权限

只有主席、管理员和活动主办部门负责人可以推进活动阶段。普通参与部门负责人只能处理本部门任务和服务事项，不能提交、开始、结束或归档整个活动。

活动详情的“添加任务”必须直接打开任务创建表单，并自动绑定当前活动。

### 4.3 主席协调中心

主席首页增加以下聚合信息：

- 有风险和需关注的活动；
- 无负责人或负责人账号失效的事项；
- 阻塞、逾期和长期未更新事项；
- 等待其他部门处理的事项；
- 各部门未完成工作量；
- 最近关键里程碑。

活动健康状态同时提供给主席和教师。排序优先级为有风险、需关注、正常，再按最近期限排序。

## 5. 统一详情体验

任务、场地、采购、白卡和组织事项采用相同的信息层次：

1. 基本信息；
2. 当前状态和下一处理人；
3. 处理流程；
4. 附件与最终成果；
5. 操作记录；
6. 当前角色可执行操作。

统一的是结构和交互规则，领域数据表、字段和状态机继续独立维护。表单提交失败时保留用户输入；所有写操作显示成功或失败反馈，并防止重复提交。

管理员导航仅保留系统治理功能。业务账号进入无权处理的模块时显示只读边界或权限说明。

## 6. 数据与接口调整

- 移除 localhost 无会话管理员回退，开发环境通过种子账号建立真实会话。
- 扩展统一工作项来源类型和投影器，领域记录仍是事实来源。
- 增加导航目标类型，前端工作区接收 `sourceType + sourceId` 并打开指定详情。
- 任务控制沿用现有 `work-controls` 和 `task-dependencies` 接口，补充页面入口、前后值审计与账号选择。
- 活动阶段权限由服务端按主办部门校验，不以“参与部门”作为活动负责人依据。
- 账号部门选项读取当前组织架构，不再使用不完整的硬编码列表。

所有迁移保持幂等，不删除历史数据。无法匹配真实账号的历史负责人继续保留姓名快照，并在协调中心列为待治理事项。

## 7. 错误处理

- 401：返回登录页并保留原始访问目标。
- 403：显示缺少的权限及当前应处理角色。
- 404：提示记录已删除或编号无效，并返回来源列表。
- 409：显示状态冲突、前置任务或阻塞原因，刷新当前详情。
- 网络或服务器错误：保留表单内容，允许重试。

## 8. 测试与验收

### 8.1 自动化测试

- 各角色真实会话登录、登出和服务端数据范围。
- 教师所有写接口返回 403。
- 活动只有主办部门负责人可推进。
- 工作项来源投影和角色待办数量。
- 各来源工作项精准跳转目标。
- 阻塞、解除、改派、延期和依赖门禁。
- 数据迁移、SQLite 与 PostgreSQL 结构一致性。

### 8.2 浏览器验收

依次使用主席、负责人、干事、办公室、学习部、新媒体和教师账号完成：

1. 主席创建活动、发布任务并配置依赖；
2. 负责人拆解子任务；
3. 干事开始、阻塞、解除并提交凭据；
4. 负责人验收并提交部门结办；
5. 主席终审；
6. 办公室处理场地和例会待办；
7. 学习部、新媒体和主席完成白卡交接；
8. 教师查看全过程且无法执行写操作。

## 9. 实施顺序

1. 真实会话与测试账号；
2. 教师只读和活动主办权限；
3. 账号部门来源与导航整理；
4. 统一工作项扩展和精准跳转；
5. 部门首页待办；
6. 任务控制页面；
7. 主席协调中心；
8. 统一详情组件和浏览器验收。

每批提交前运行完整检查，推送后确认 GitHub CI。整改期间保留既有活动、任务和部门业务数据。
