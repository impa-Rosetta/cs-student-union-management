# 教师活动监管中心设计说明

## 1. 背景与目标

教师当前工作台包含演示性质的统计数字和待指导事项，只能按指导教师姓名看到少量活动，无法回答“一个活动现在推进到哪里、各部门负责人和干事分别在做什么、哪些任务已经逾期”这类监管问题。

本次建设一个面向教师的只读活动监管中心。教师可以查看系统中的全部活动，并从活动总览逐层进入部门负责人任务、干事子任务和实际操作记录。页面采用项目管理中常见的 WBS（工作分解结构）与甘特时间轴组合，不再使用静态演示数据。

成功标准：

1. 教师登录后可以查看全部活动，而非仅查看本人指导的活动。
2. 每个活动能够按“活动 → 部门负责人任务 → 干事子任务”展示完整分工。
3. 时间轴能够显示计划开始、计划完成、当前状态、负责人和逾期情况。
4. 活动总体进度由下级任务自动汇总，不依赖手工填写的百分比。
5. 教师能够查看与活动有关的创建、分派、提交、审核、退回、完成和归档记录。
6. 教师只能读取数据，不能审批、修改、删除、上传附件或改变任何状态。

## 2. 范围边界

### 2.1 本期实现

- 教师监管总览和活动搜索、状态筛选、部门筛选。
- 活动级进度、任务总数、已完成数、逾期数和最近截止日期。
- WBS 层级任务列表与甘特时间轴。
- 活动、负责人任务、干事子任务的详情查看。
- 活动相关流程事件的统一时间线。
- 附件只读查看与下载。
- 负责人和干事现有任务创建界面补充标准化的计划起止时间。
- 将任务与活动由活动名称关联升级为稳定的活动 ID 关联。

### 2.2 本期不实现

- 教师填写意见、审批、退回、催办或修改数据。
- 关键路径计算、资源负载计算和自动排期。
- 任务依赖线及前置任务约束。
- 单独的“大型活动”标识；全部活动均进入监管范围。
- 按教师分配可见范围；所有教师账号拥有相同的活动只读范围。
- 修改办公室、学习部、生活部等已有业务流程。

## 3. 方案选择

采用“监管总览 + WBS 甘特图 + 操作记录”的组合方案。

未采用纯操作日志方案，因为它只能说明发生过什么，不能直观看出计划、分工和逾期。未采用纯人员时间轴方案，因为同一人员可能承担多个不同层级的任务，活动完成情况也无法由人员维度稳定汇总。WBS 方案直接复用现有活动、任务和子任务关系，既符合项目管理惯例，也最适合当前系统规模。

## 4. 信息架构与页面

### 4.1 教师监管总览

教师工作台改为真实数据驱动，顶部展示：

- 活动总数；
- 进行中活动数；
- 逾期任务数；
- 七日内到期任务数。

主体为活动卡片或紧凑列表。每项展示活动名称、状态、举办时间、地点、组织者、自动汇总进度、任务完成数、逾期数和最近截止日期。默认按“存在逾期 → 最近截止时间 → 最近更新”排序。

页面提供关键词、活动状态和参与部门筛选。教师选择活动后进入监管详情，不再进入可编辑的普通活动办理界面。

### 4.2 活动监管详情

详情页分为三个区域：

1. **活动摘要**：活动基本信息、总体进度、负责人任务数、干事子任务数、逾期数和无负责人任务数。
2. **执行时间轴**：核心 WBS 甘特图。
3. **操作记录**：按时间倒序排列的真实流程事件。

### 4.3 WBS 甘特时间轴

左侧固定信息区按以下层级展示：

```text
活动
├─ 部门负责人任务
│  ├─ 干事子任务
│  └─ 干事子任务
└─ 部门负责人任务
```

每行显示名称、所属部门、负责人或干事、状态和计划截止时间。活动和负责人任务可以折叠。

右侧时间区以日或周为刻度绘制横向计划条：

- 绿色：已完成；
- 蓝色：正常进行；
- 灰色：尚未开始；
- 橙色：临近截止；
- 红色：已逾期或明确标记风险；
- “今天”使用竖向参考线标识。

首版只读，不支持拖动排期。没有标准计划日期的历史任务仍然展示在层级列表中，时间区以“日期未完善”标识，不伪造时间条。

点击任意行打开只读详情抽屉，展示说明、计划时间、实际状态、完成要求、完成说明和附件。活动行的日期范围由所有有效子项的最早计划开始时间和最晚计划完成时间自动汇总；负责人任务的进度由其子任务汇总。

### 4.4 操作记录时间线

操作记录统一汇总以下实体的 `workflow_events`：

- 当前活动自身；
- 通过 `activity_id` 关联到活动的负责人任务；
- 上述负责人任务的干事子任务。

记录显示操作时间、操作者、角色、动作、状态变化、原因或备注以及所属对象。动作名称在展示层转换为中文，例如创建、分派、开始、提交、审核通过、退回、完成和归档。记录不可编辑。

## 5. 数据设计

### 5.1 任务的稳定活动关联

在 `tasks` 表增加：

- `activity_id TEXT NOT NULL DEFAULT ''`
- `planned_start_at TEXT NOT NULL DEFAULT ''`
- `planned_end_at TEXT NOT NULL DEFAULT ''`

保留 `activity_name` 作为快照和历史兼容字段，但所有新任务必须使用 `activity_id` 关联活动。读取历史数据时，如果 `activity_id` 为空，可以在名称唯一的前提下按 `activity_name` 匹配；存在重名时保持未关联，避免错误归属。

### 5.2 子任务计划日期

在 `subtasks` 表增加：

- `planned_start_at TEXT NOT NULL DEFAULT ''`
- `planned_end_at TEXT NOT NULL DEFAULT ''`

继续通过 `parent_task_id` 关联负责人任务。旧的 `deadline` 字段保留用于兼容和人类可读展示；新建或编辑任务时同步写入标准 ISO 日期字段。

### 5.3 进度计算

活动进度按照可执行叶子节点计算：

- 有子任务的负责人任务，其子任务作为叶子节点；
- 没有子任务的负责人任务自身作为叶子节点；
- 完成状态为 `已完成`；
- 活动归档不自动把未完成叶子节点视为完成。

公式为：`已完成叶子节点数量 ÷ 全部叶子节点数量 × 100%`。没有任务的活动显示 0%，并标记“尚未分工”。负责人任务进度使用相同规则对其子任务计算；无子任务时根据自身状态显示 0% 或 100%。

### 5.4 逾期和临期规则

- 计划完成时间早于当前时间且状态不是已完成：逾期；
- 未来七日内到期且未完成：临期；
- 原任务 `risk` 为真时始终显示风险提示；
- 缺少计划完成时间时标记“日期未完善”，不计为逾期。

所有时间比较使用 ISO 时间值，界面按 Asia/Shanghai 显示。

## 6. 服务与权限

新增只读聚合接口：

- `GET /api/teacher-supervision`：返回活动监管总览；
- `GET /api/teacher-supervision?activityId=<id>`：返回单个活动、关联任务、子任务和事件。

接口只接受已登录的 `teacher`、`admin` 账号。教师端正常入口仅对 `teacher` 展示；管理员保留排障查看能力。接口不提供 POST、PATCH 或 DELETE 方法。

聚合服务负责：

1. 读取活动、任务、子任务和流程事件；
2. 按稳定 ID 建立层级；
3. 计算进度、逾期、临期和日期范围；
4. 过滤与活动无关的数据；
5. 返回专用 DTO，避免前端直接依赖数据库行结构。

教师继续通过现有附件接口查看文件。附件接口必须维持登录和角色校验；监管页面不展示删除、替换或上传按钮。

## 7. 前端组件边界

- `TeacherSupervisionDashboard`：加载总览、筛选活动、展示统计。
- `ActivitySupervisionDetail`：加载并组织单个活动详情。
- `SupervisionTimeline`：只负责 WBS 层级和时间条绘制。
- `SupervisionEventLog`：只负责操作记录展示。
- `SupervisionDetailDrawer`：展示活动、任务或子任务的只读资料。
- `teacher-supervision/service.ts`：服务器端聚合、日期和进度计算。
- `teacher-supervision/types.ts`：定义接口 DTO，隔离存储模型与界面模型。

组件不直接修改任务状态，也不复用带审批按钮的任务抽屉，以确保只读边界清晰。

## 8. 数据流

```text
教师打开工作台
  → GET /api/teacher-supervision
  → 权限校验
  → 活动、任务、子任务聚合
  → 计算进度和风险
  → 返回活动监管摘要

教师选择活动
  → GET /api/teacher-supervision?activityId=...
  → 校验活动存在
  → 读取关联任务、子任务及 workflow_events
  → 构造 WBS 与事件时间线
  → 页面只读展示
```

负责人或干事在原工作台更新任务后，原有流程继续写入关系表和 `workflow_events`。教师下次加载或点击刷新即可看到最新状态，本期不引入 WebSocket 实时推送。

## 9. 异常与兼容处理

- 未登录：返回 401。
- 非教师或管理员访问监管接口：返回 403。
- 活动不存在：返回 404。
- 单条历史任务缺少活动 ID：仅在活动名称唯一时兼容归属。
- 日期为空或无法解析：保留任务但标记“日期未完善”。
- 单条事件字段缺失：使用可读的默认说明，不阻断整个活动详情。
- 接口加载失败：页面保留当前筛选条件，显示重试按钮。
- 活动没有任务：显示“尚未分工”，而不是空白时间轴。

迁移同时更新 SQLite/Drizzle 定义、PostgreSQL 建表脚本和迁移一致性测试，保证本地与部署环境一致。

## 10. 测试与验收

### 10.1 单元测试

- WBS 构建：活动、任务和子任务层级正确。
- 进度汇总：有子任务、无子任务和空活动三种情况正确。
- 日期范围：父项从子项正确汇总，缺失日期不产生虚假时间条。
- 逾期与临期：边界时间、已完成任务和风险任务判断正确。
- 历史名称兼容：仅唯一活动名称可以补充归属。
- 事件过滤：不会混入其他活动的任务和子任务事件。

### 10.2 接口测试

- 教师和管理员可读，其他角色被拒绝。
- 接口不存在写方法。
- 总览统计与详情数据一致。
- 不存在的活动返回 404。

### 10.3 页面测试

- 教师总览不再包含硬编码统计和演示待办。
- 筛选、折叠、详情抽屉和附件链接可用。
- 不渲染编辑、审批、退回、删除或上传操作。
- 桌面端可完整显示时间轴，窄屏可横向滚动且左侧任务信息保持可读。

### 10.4 回归验证

运行项目完整检查命令，确保现有活动流程、负责人任务、干事子任务、部门工作台和数据库迁移一致性测试继续通过。最后使用教师测试账号进行端到端体验：总览全部活动、进入一个有多部门分工的活动、展开干事子任务、查看逾期标识和操作记录。

## 11. 实施顺序

1. 完成数据库字段与迁移。
2. 统一任务创建、更新时的活动 ID 和计划日期写入。
3. 实现监管聚合服务及权限接口。
4. 实现教师总览和活动监管详情。
5. 补齐样例数据，使体验环境能展示多部门、多层级和逾期状态。
6. 完成单元、接口、页面及全量回归测试。
