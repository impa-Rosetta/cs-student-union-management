# 办公室办事中心 MVP 设计

## 目标

把办公室最适合信息化的两类工作——场地申请和报销申请——纳入现有学生联盟管理系统，形成可提交、可退回、可跟踪、可追溯的闭环。

## 范围

- 场地申请：记录关联活动、使用时间、人数、教室类型、设备需求、外部办理平台、外部单号和办理结果。
- 报销申请：记录关联活动、金额、费用类别、收款人、预算项目、材料清单和支付状态。
- 统一状态：草稿 → 已提交 → 办公室审核 → 外部办理中 → 已完成；审核阶段允许退回补充材料或驳回。
- 每次状态变化保存操作人、时间、原状态、新状态和备注。
- 所有登录成员可查看；学生组织成员可提交；办公室成员、主席和管理员可受理与推进。

## 不在本期范围

- 不自动登录学校 OA、教务或财务平台。
- 不直接执行财务付款。
- 二课审核、活动发布补签和每周例会材料暂不进入本次 MVP。

## 数据模型

统一使用 `office_requests` 表保存申请基础信息和两类业务详情，材料清单以 JSON 保存；使用 `office_request_events` 保存操作轨迹。申请通过 `activity_id` / `activity_name` 关联现有活动。

## 界面

侧边栏新增“办公室办事”，包含统计卡片、类型与状态筛选、申请列表、详情时间线和新建申请表单。不同申请类型显示各自字段与材料检查项。

## 权限

- admin / chair / 办公室成员：可受理、退回、驳回、登记外部办理并完成。
- leader / staff：可创建申请、提交草稿，并查看处理进度。
- teacher：只读。

## 验收标准

用户可以创建一份场地或报销申请并提交；管理人员可以将其推进到完成或退回；刷新页面后数据仍存在；详情中能看到材料清单和完整处理轨迹；越权操作由服务端拒绝。
