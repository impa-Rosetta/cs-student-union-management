# 角色体验与协调工作台实施计划

依据：`docs/superpowers/specs/2026-11-05-role-experience-and-coordination-redesign.md`

## 第一批：真实身份与权限边界

1. 为本地环境提供幂等测试账号种子，覆盖管理员、主席、负责人、干事、办公室、学习部、新媒体和教师。
2. 移除 localhost 无会话管理员回退；未登录 API 返回 401。
3. 本地统一使用邮箱密码登录，退出后返回同一登录页。
4. 账号创建/编辑的部门选项读取组织架构。
5. 教师所有写操作返回 403，移除前端写入口。
6. 活动阶段仅主办部门负责人可推进。
7. 增加认证、教师只读、活动主办权限集成测试。

## 第二批：统一待办与精准跳转

1. 扩展工作项来源：例会通报、组织异动、组织事务。
2. 为各来源补充状态、下一处理人和角色范围投影。
3. 定义统一导航目标并由“我的工作”传递来源编号。
4. 主任务直接打开详情；子任务打开父任务并定位子任务；部门服务打开指定记录。
5. 各工作区支持外部指定记录并在打开后清除目标。
6. 增加来源投影、权限范围和导航目标测试。

## 第三批：部门首页与任务控制

1. 部门负责人/干事首页读取统一待办摘要。
2. 办公室、生活部、组织部、学习部和新媒体展示专属待办。
3. 在任务详情接入阻塞、解除、改派、延期操作。
4. 在主席任务详情增加依赖配置与前置状态展示。
5. 活动详情“添加任务”打开绑定当前活动的创建表单。
6. 增加任务控制交互与服务端审计测试。

## 第四批：主席协调与体验统一

1. 建立主席协调聚合：风险活动、无负责人、阻塞、逾期、长期等待、部门负荷和里程碑。
2. 将活动健康状态接入主席首页。
3. 精简管理员导航为系统治理入口。
4. 提取通用详情区块，逐步替换重复页面结构。
5. 完成全角色浏览器验收、迁移演练、完整构建和部署检查。

## 提交与验收

- 每一批独立提交并推送。
- 每批至少执行类型检查、相关集成测试和迁移一致性测试。
- 推送前执行 `npm run check`，推送后确认 GitHub CI。
- 不删除现有业务数据；种子、迁移和工作项投影必须幂等。
