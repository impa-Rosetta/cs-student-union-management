# 部署与测试手册

## 一、发布前检查

在项目目录执行：

```bash
npm install
npm test
npm run lint
```

只有三项均通过后再发布。首次部署使用空的线上 D1 和 R2，避免把本地演示数据误当成正式数据。

## 二、私有部署

1. 创建私有站点并部署当前提交。
2. 站点所有者打开部署地址并完成登录，系统自动建立首个管理员账号。
3. 进入“账号与权限”，按测试者真实邮箱新增账号。
4. 为每个账号设置姓名、身份、部门和数据范围。
5. 在站点访问控制中加入同一批邮箱。

站点白名单决定谁能访问网址，系统账号决定进入后能做什么。两者缺一不可。

## 三、建议测试账号

准备五个可以实际登录的邮箱，分别配置为：系统管理员、主席、运维部负责人、运维部干事、教师。若邮箱数量不足，可以先覆盖主席、负责人和干事三条主流程。

## 四、完整验收流程

1. 主席创建一个测试活动，填写时间、地点、指导教师和参与部门。
2. 主席在活动中发布主任务，执行人既要测试负责人，也要测试普通干事。
3. 负责人打开部门主任务，拆分子任务并分派给干事。
4. 干事开始任务，上传图片和文档凭据，删除一个附件后重新上传。
5. 干事提交验收，再撤回提交，修改说明后再次提交。
6. 负责人退回一次，干事修改后重交，负责人验收通过。
7. 负责人提交部门结办，再撤回一次，最后重新提交。
8. 主席查看子任务执行人、凭据和动态，审核主任务通过。
9. 教师查看被授权活动并提交指导意见。
10. 管理员停用一个测试账号，确认该账号重新访问时被拒绝。

## 五、跨设备一致性

主席和负责人分别在两个浏览器或两台设备登录。任意一端改变任务状态后，另一端刷新页面，应看到同一状态、附件和通知。通知已读状态属于个人数据，不要求在不同账号之间一致。

## 六、问题反馈格式

每个问题至少记录：登录身份、操作入口、复现步骤、预期结果、实际结果、发生时间和截图。附件问题还要注明文件类型与大小。

## 七、上线前处理

- 删除验收期间创建的测试任务和测试附件。
- 导入真实成员前再次核对届次、部门和职务。
- 确认站点仍为 Private，访问名单中没有无关邮箱。
- 保留一个独立管理员账号，不把日常主席账号设为唯一管理员。
- 每次更新先部署测试版本，验证通过后再切换正式版本。
